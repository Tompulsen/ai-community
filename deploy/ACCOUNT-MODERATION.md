# 社区账号封禁与举报

2026-11-07。本轮为本地实现，尚未发布或在生产数据库运行迁移。

## 管理入口

- `/admin/community`：账号封禁规则。默认启用，阈值 3 次，允许 1–1000 的整数；可关闭自动封禁。发布审核设置继续沿用原有功能。
- `/admin/users` → 用户详情：手动封禁、解封，以及历史违规总数和本轮违规次数。
- `/admin/abuses`：查看举报原因、目标链接及举报时的内容快照，确认违规、驳回或其他处理。沿用原有管理员通知渠道。
- 社区作品卡片、作品详情和评论：新增举报入口，游客先登录；提交失败保留原因，15 秒超时恢复重试。

## 计数规则

1. 作品与评论违规合并累计。举报提交本身不增加违规次数。
2. 作品“违规下架”计数；普通驳回不计数，除非勾选“确认此作品违规，驳回时计入违规次数”。
3. 接受通过新举报入口提交的作品或评论举报计数。未关联具体内容的旧账号举报保持原有处理方式，不自动累计。
4. 同一作品或评论最多计数一次，包括多人举报、请求重试和作品审核与举报交叉处理；修改同一作品也不会重复累计。
5. 阈值修改不追溯封禁，下次确认新的违规时检查；管理员和审核员受原生权限保护，不自动封禁。
6. 解封保留历史，使用解封时的累计数作为基线，本轮重新从零累计。再次调用已解封账号的解封接口不会清空新增违规。
7. 复用原生账号停用状态，受保护写入 API 拒绝被封禁账号，公开作品查询排除被封禁作者。没有新增自动内容识别模型；违规由审核人员确认。
8. 接受举报只处理举报与账号计数。需要下架作品时进入作品审核，需要删除评论时使用原评论页面；界面确认中会提示。

## 数据与发布

新增 `community_violation` 去重凭据表、用户累计数及解封基线、举报内容标识和快照。新增迁移 `1794022723183-community-account-moderation.js` 提供 up/down。新增凭据、计数、自动封禁同事务提交；原生缓存通知等副作用在提交后执行。服务端核对目标归属与可见性，不接受客户端提供的被举报人 ID。

发布时先使用项目正常流程完成依赖安装和前后端构建，在备份后运行新增迁移，再启动更新的后端和前端。仅回滚应用通常可保留新增列与证据表；down 会删除本功能数据，不能作为无损回滚。
